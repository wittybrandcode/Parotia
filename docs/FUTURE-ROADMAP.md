## 1. الرؤية

تحويل محرر Parotia من أداة رسم نهائي فوق لقطة شاشة إلى مساحة عمل تحرير احترافية وخفيفة، تحافظ على دقة الالتقاط الحالية وتسمح للمستخدم بإعادة تعديل النصوص والأشكال والطبقات دون فقدان الجودة أو الأصل.

النتيجة المطلوبة ليست منافسة برامج التصميم العامة، بل تقديم الأدوات الأكثر فائدة للصحفي وصانع المحتوى داخل تدفق سريع وآمن:

1. التقاط مطابق للصفحة.
2. توضيح المحتوى بصرياً دون إتلاف الأصل.
3. حفظ العمل ومراجعته.
4. تصديره أو مشاركته بالجودة والمقاس المناسبين.

## 2. مبادئ التصميم الملزمة

- **تحرير غير هدّام:** لا تُدمج النصوص والأشكال مع الصورة إلا عند التصدير النهائي.
- **فصل مساحة العمل عن الناتج:** الزوم والتحريك والشبكة وأدلة المحاذاة لا تغيّر أبعاد الصورة المصدّرة.
- **نموذج واحد للحالة:** الطبقات، التحديد، التحويلات، Undo/Redo والحفظ تعتمد نموذج مستند موحداً.
- **الدقة أولاً:** لا تُعاد كتابة مسار الالتقاط المستقر من أجل خصائص المحرر.
- **دعم العربية أصلياً:** اتجاه RTL، تشكيل الحروف، المحاذاة، التفاف الأسطر والخطوط ليست تحسينات لاحقة.
- **الخصوصية افتراضياً:** Clipboard والتنزيل وWeb Share محلية؛ الروابط السحابية خارج النطاق حتى اعتماد خدمة واضحة.
- **قابلية الاسترجاع:** كل عملية تحرير قابلة للتراجع، وكل مشروع محفوظ يحمل إصدار مخطط بيانات قابل للترحيل.
- **أداء محدود الموارد:** أحجام Canvas، الصور، سجل التاريخ والتخزين المؤقت تخضع لحدود معلنة واختبارات ضغط.

## 3. نظام الأولويات والتتبع

### حالات التنفيذ

| الرمز | الحالة | المعنى |

| `[~]` | قيد التنفيذ | يوجد فرع عمل واختبارات جارية |

## 4. الأهداف المستقبلية

### FND — نموذج المستند والتحرير غير الهدّام (`P0`)

الهدف هو إنشاء تمثيل متسلسل لكل ما يظهر في المحرر، بدلاً من الرسم المباشر النهائي على الصورة.

- [ ] `FND-01` تعريف `EditorDocument` بإصدار مخطط واضح، وأبعاد اللوحة وخلفيتها وطبقاتها.
- [ ] `FND-02` تعريف أنواع طبقات مستقرة: صورة، نص، مستطيل، دائرة، خط، سهم ووسم توضيحي.
- [ ] `FND-03` منح كل طبقة معرفاً ثابتاً، ترتيباً، رؤية، قفلاً، شفافية وتحويلاً هندسياً.
- [ ] `FND-04` توحيد الأوامر مع Undo/Redo محدود الذاكرة وقابل للاختبار.
- [ ] `FND-05` فصل عرض المستند عن عملية Flatten/Export النهائية.
- [ ] `FND-06` إضافة ترحيل للإصدارات المستقبلية من صيغة المشروع.

**معيار الخروج:** فتح مستند، إضافة عناصر، تعديلها، التراجع عنها، تسلسلها وإعادة تحميلها دون اختلاف مرئي أو فقدان بيانات.

### VPT — الزوم والتحريك الاحترافي (`P0`)

- [ ] `VPT-01` زوم متمركز حول موضع المؤشر دون قفز اللوحة.
- [ ] `VPT-02` أوضاع `Fit` و`Fill` و`100%` ونسب مخصصة ضمن حدود آمنة.
- [ ] `VPT-03` Pan عبر زر الفأرة الأوسط أو `Space + Drag` مع دعم لوحة اللمس.
- [ ] `VPT-04` اختصارات `Ctrl/Cmd + +` و`Ctrl/Cmd + -` و`0` و`1`.
- [ ] `VPT-05` مؤشر نسبة الزوم وإعادة تمركز اللوحة.
- [ ] `VPT-06` رسم HiDPI واضح دون تغيير بكسلات التصدير.
- [ ] `VPT-07` أداء سلس على الصور الكبيرة مع تجنب إعادة الرسم غير الضرورية.

**معيار الخروج:** يبقى البكسل الواقع تحت المؤشر ثابتاً أثناء الزوم، ولا تتأثر أبعاد أو جودة ملف التصدير بنسبة عرض مساحة العمل.

### LYR — نظام الطبقات والتحديد (`P0`)

- [ ] `LYR-01` لوحة طبقات بترتيب أمامي/خلفي مع Drag & Drop.
- [ ] `LYR-02` تحديد طبقة واحدة أو عدة طبقات من اللوحة أو مساحة العمل.
- [ ] `LYR-03` تحريك وتكبير وتصغير وتدوير العناصر بعد إنشائها.
- [ ] `LYR-04` إخفاء وقفل ونسخ وحذف وإعادة تسمية الطبقة.
- [ ] `LYR-05` Group/Ungroup مع الحفاظ على التحويلات النسبية.
- [ ] `LYR-06` محاذاة وتوزيع العناصر المختارة.
- [ ] `LYR-07` نسخ/لصق الطبقات داخل المشروع وبين مشاريع متوافقة.
- [ ] `LYR-08` ترتيب Keyboard Focus وإتاحة العمليات دون فأرة.

**معيار الخروج:** كل عنصر مرئي قابل لإعادة التحديد والتحرير ولا يتحول إلى بكسلات نهائية قبل التصدير.

### SNP — المحاذاة والأدلة (`P1`)

- [ ] `SNP-01` Snap إلى حواف ومركز اللوحة.
- [ ] `SNP-02` Snap إلى حواف ومراكز الطبقات الأخرى.
- [ ] `SNP-03` أدلة محاذاة ومسافات ذكية تظهر أثناء السحب.
- [ ] `SNP-04` شبكة اختيارية قابلة لضبط المسافة واللون.
- [ ] `SNP-05` مساطر وأدلة يدوية قابلة للسحب والقفل.
- [ ] `SNP-06` تعطيل مؤقت للمحاذاة أثناء السحب عبر مفتاح مساعد.

### TXT — النصوص الاحترافية ودعم العربية (`P1`)

- [ ] `TXT-01` إعادة تحرير المحتوى النصي بعد إنشائه.
- [ ] `TXT-02` اختيار الخط والحجم والوزن والنمط واللون.
- [ ] `TXT-03` دعم RTL/LTR والمحاذاة والتفاف الأسطر بصورة صحيحة.
- [ ] `TXT-04` تباعد الأسطر والحروف وحدود صندوق النص.
- [ ] `TXT-05` خلفية وحد وظل وشفافية للنص.
- [ ] `TXT-06` قائمة خطوط آمنة مع اكتشاف الخطوط المتاحة محلياً وفallback واضح.
- [ ] `TXT-07` حفظ خصائص الخط في المشروع وإظهار بديل صريح عند غياب الخط.
- [ ] `TXT-08` أنماط نصية قابلة لإعادة الاستخدام للعناوين والاقتباسات والتعليقات.

### SHP — الأشكال والتوضيحات (`P1`)

- [ ] `SHP-01` مستطيل، مستطيل دائري، دائرة، خط، سهم وCallout.
- [ ] `SHP-02` تعبئة وحد وسماكة ونمط خط وشفافية قابلة للتعديل.
- [ ] `SHP-03` رؤوس أسهم متعددة واتجاه قابل للعكس.
- [ ] `SHP-04` ترقيم خطوات تلقائي مع استمرار التسلسل.
- [ ] `SHP-05` نسخ تنسيق عنصر وتطبيقه على عنصر آخر.
- [ ] `SHP-06` Presets متناسقة بصرياً للاستخدام الصحفي السريع.

### SHR — المشاركة والتصدير (`P1`)

- [ ] `SHR-01` نسخ الصورة النهائية إلى Clipboard مع معالجة فشل الصلاحية بوضوح.
- [ ] `SHR-02` استخدام Web Share API عندما يكون متاحاً، مع مسار بديل للتنزيل أو النسخ.
- [ ] `SHR-03` تصدير PNG وJPEG وWebP وفق دعم المتصفح.
- [ ] `SHR-04` ضبط الجودة والخلفية والشفافية والمقياس `1× / 2× / 3×` ضمن حدود الذاكرة.
- [ ] `SHR-05` عرض الأبعاد والحجم التقديري قبل التصدير.
- [ ] `SHR-06` Presets لمنصات X وFacebook وInstagram وLinkedIn دون قص صامت للمحتوى.
- [ ] `SHR-07` أسماء ملفات آمنة وقابلة للتخصيص مع إزالة البيانات الوصفية غير الضرورية.
- [ ] `SHR-08` توحيد Copy/Share/Save عبر Export Pipeline واحدة لمنع اختلاف الناتج.
- [ ] `SHR-09` منع تكرار النقرات والعمليات المتزامنة وإظهار تقدم قابل للإلغاء.

**قرار خصوصية:** إنشاء روابط عامة أو رفع الصور إلى خدمة خارجية هدف `P3` منفصل، ولا يبدأ قبل اعتماد نموذج تهديد، سياسة احتفاظ، تشفير، حذف وموافقة صريحة من المستخدم.

### PRJ — حفظ المشاريع واستعادتها (`P1`)

- [ ] `PRJ-01` حفظ مشروع Parotia يتضمن الأصل والطبقات والإعدادات وإصدار المخطط.
- [ ] `PRJ-02` فتح المشروع ومتابعة العمل دون Flatten.
- [ ] `PRJ-03` Autosave محلي محدود السعة مع سياسة LRU واضحة.
- [ ] `PRJ-04` استعادة آمنة بعد إغلاق المحرر أو تعطل المتصفح.
- [ ] `PRJ-05` قائمة مشاريع حديثة مع إعادة تسمية ونسخ وحذف قابل للتأكيد.
- [ ] `PRJ-06` تحذير عند فقد خط أو أصل أو عدم توافق إصدار المشروع.
- [ ] `PRJ-07` تصدير/استيراد ملف مشروع محمول مع تحقق صارم من النوع والحجم والمخطط.

### EDT — أدوات صحفية وخصوصية (`P2`)

- [ ] `EDT-02` Redaction آمن يزيل البكسلات المخفية فعلياً عند التصدير، لا يغطيها بصرياً فقط.
- [ ] `EDT-03` Highlight وSpotlight لتوجيه الانتباه إلى منطقة محددة.
- [ ] `EDT-04` Eyedropper لاختيار لون من الصورة.
- [ ] `EDT-05` شعار/Watermark مع موضع وهوامش وشفافية Preset.
- [ ] `EDT-06` قوالب عناوين واقتباسات وهوية بصرية محلية.
- [ ] `EDT-07` معاينة Before/After دون تعديل المستند.
- [ ] `EDT-08` فحص تلقائي اختياري للمناطق التي قد تحتوي معلومات حساسة دون إرسال الصورة لخادم.

### LRG — الصور الكبيرة وحدود المحرر (`P0`)

الهدف هو منع انهيار المحرر أو التبويب عند فتح لقطات ضخمة، مع عدم فرض حد ثابت اعتباطي على جميع الأجهزة. يعتمد القرار على أبعاد الصورة، عدد البكسلات، الذاكرة المفكوكة والأسطح المؤقتة المطلوبة، ثم يختار أعلى نمط آمن بصورة واضحة للمستخدم.

- [ ] `LRG-01` تعريف `EditorCapabilityBudget` يقيس حدود Canvas الفعلية، عدد البكسلات الآمن، ذاكرة الصورة المفكوكة وميزانية الأسطح المؤقتة لكل جلسة.
- [ ] `LRG-02` تنفيذ Preflight قبل فتح المحرر يحسب كلفة الأصل، Preview، الطبقات، History والتصدير قبل تخصيص Canvas كبير.
- [ ] `LRG-03` اعتماد ثلاثة أوضاع معلنة: تحرير كامل، تحرير Proxy مع أصل كامل الدقة، أو تجاوز المحرر مع تنزيل/تقسيم الصورة عندما تتجاوز القدرة الآمنة.
- [ ] `LRG-04` بناء Renderer مبلّط يرسم البلاطات المرئية فقط ويفرغ البلاطات البعيدة وفق سياسة LRU، بدل إبقاء الصورة كلها في Canvas واحد.
- [ ] `LRG-05` إنشاء هرم معاينات متعددة الدقة للزوم والتحريك السلس، مع إبقاء الأصل غير المعدل مرجعًا للتصدير النهائي.
- [ ] `LRG-06` تحويل History للصور الكبيرة من لقطات PNG كاملة إلى أوامر وفروق محدودة الذاكرة مع Checkpoints دورية قابلة للاستعادة.
- [ ] `LRG-07` استبدال نسخ Data URL المتكررة بمسار Blob/Object URL وتخزين مؤقت مجزأ، مع تنظيف حتمي عند الحفظ والإغلاق والتعطل.
- [ ] `LRG-08` تنفيذ تصدير مبلّط أو عبر Worker/OffscreenCanvas عند توفره، مع تقدم قابل للإلغاء ومنع إنشاء أكثر من سطح تصدير ضخم في الوقت نفسه.
- [ ] `LRG-09` اكتشاف ضغط الذاكرة وفشل التخصيص، خفض جودة المعاينة تلقائيًا، واستعادة العمل دون فقد الأصل أو إغلاق المحرر بصمت.
- [ ] `LRG-10` اختبارات ضغط على مصفوفة أبعاد/DPR وميزانيات ذاكرة منخفضة، تشمل رفضًا آمنًا ورسائل دقيقة وعدم انهيار التبويب.

| نتيجة Preflight | السلوك المطلوب |
|---|---|
| ضمن الميزانية الآمنة | فتح المحرر بكامل الدقة والخصائص |
| الأصل آمن لكن أسطح التحرير الكاملة مكلفة | فتح Proxy مبلّط مع تصدير من الأصل كامل الدقة |
| فك الصورة أو التصدير يتجاوز قدرة المتصفح | عدم فتح محرر غير مستقر؛ عرض الأبعاد والحد والخيارات: تنزيل الأصل، التقسيم، أو التقاط جزء |

**معيار الخروج:** لا تؤدي أي صورة مدعومة إلى تجمد الواجهة أو انهيار التبويب، ولا تُخفّض دقة التصدير بصمت. يعرف المستخدم قبل التحرير النمط المستخدم وحدوده، ويظل الأصل محفوظًا حتى النجاح أو الإلغاء.

## 5. ترتيب التنفيذ المقترح

| المرحلة | النطاق | الاعتماد | بوابة الخروج |
|---|---|---|---|
| `M0` التصميم | عقود المستند، UX للطبقات، ميزانية الصور الكبيرة وملف المشروع | خط أساس `1.4.1` | قرارات معمارية ونماذج UX معتمدة |
| `M1` الأساس | `FND` + إعادة بناء History حول الأوامر | `M0` | مستند قابل للتسلسل والاستعادة دون فقد |
| `M2` مساحة العمل | `VPT` + `LRG` + أساس `SNP` | `M1` | زوم/Pan دقيقان ومحرر كبير الصور محدود الذاكرة |
| `M3` التأليف | `LYR` + `TXT` + `SHP` | `M1`, `M2` | عناصر قابلة لإعادة التحرير مع دعم عربي |
| `M4` الإخراج | `SHR` + Export Pipeline موحدة | `M3` | Copy/Share/Save متطابقة وقابلة للاختبار |
| `M5` الاستمرارية | `PRJ` | `M1`, `M3` | حفظ واستعادة وترحيل مشروع كامل |
| `M6` الأدوات الصحفية | `EDT` | `M3`, `M4` | أدوات الخصوصية والتوضيح غير هدامة |
| `M7` التثبيت | جميع بنود `QLT` المتبقية | `M1–M6` | إصدار مرشح بلا أعطال معروفة في المسارات الحرجة |

لا يُنصح بتنفيذ لوحة الطبقات كواجهة مستقلة قبل `FND`، أو تنفيذ الزوم بتغيير أبعاد الصورة، أو إنشاء كل أداة بسجل Undo خاص بها؛ هذه الاختصارات ستجعل إعادة التحرير والحفظ غير موثوقين.

## 6. تقسيم الإصدار المقترح

### مرشح `1.5.x`

يمكن إصداره كتطوير محافظ إذا اقتصر على:

- الزوم والتحريك المهنيان.
- تحسين Share/Copy/Export باستخدام النموذج الحالي.
- بوابة Preflight وحدود معلنة للصور الكبيرة، ثم Preview مبلّط إذا لم يتطلب تغيير صيغة المستند.
- تحسينات أداء وإتاحة لا تغيّر صيغة المستند.

### مرشح `2.0.0`

يصبح أنسب عند إدخال:

- نموذج المستند الجديد.
- الطبقات القابلة للتحرير والحفظ.
- صيغة مشروع Parotia.
- تغيير جوهري في Undo/Redo وFlatten.

يُحسم رقم الإصدار بعد `M0` وفق حجم التغيير وتوافق المشاريع، وليس وفق الرغبة التسويقية فقط.

## 7. تعريف الاكتمال لأي هدف

لا ينتقل أي بند إلى `[x]` إلا عند تحقق الآتي:

1. توثيق سلوك المستخدم والحالات الفارغة والفشل والإلغاء.
2. وجود عقد TypeScript واضح وحدود مدخلات ومخرجات.
3. عدم دمج التعديل مع الصورة قبل التصدير، ما لم يكن ذلك مقصوداً وموثقاً مثل Redaction النهائي.
4. اختبارات وحدات للحسابات والحالة، واختبار تكامل للمسار، وE2E للخصائص الحرجة.
5. اجتياز `typecheck` و`lint` و`test` و`build` و`e2e` وSonar دون تجاوزات صامتة.
6. قياس الأداء والذاكرة على أحجام الصور المعتمدة.
7. دعم لوحة المفاتيح وRTL ورسائل الخطأ القابلة للفهم.
8. تحديث الوثائق والاختصارات وChangelog قبل الدمج.
